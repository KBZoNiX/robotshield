1. Antes de empezar

1.1 Preparar el Arduino IDE

  1. Abrir el Arduino IDE.
  2. En Herramientas → Placa, elegir Arduino Uno.
  3. Conectar el Arduino por USB y elegir el puerto en Herramientas → Puerto (en Ubuntu suele ser /dev/ttyACM0 o /dev/ttyUSB0).
  4. Abrir el archivo principal del programa: TestPlaca.ino, Futbol.ino o MiniSumo.ino. El IDE abre automáticamente las demás pestañas de esa carpeta.
  5. Presionar Verificar (✔) para compilar y Subir (→) para cargar el programa.
⚠ Desconectar el HC-05 antes de subir un programa El módulo Bluetooth HC-05 está conectado a los pines D0 y D1. Son los mismos pines que usa el cable USB para cargar el programa. Si el HC-05 está enchufado en J4, la carga falla. Primero se desconecta el HC-05, después se sube el programa y al final se vuelve a conectar.
⚠ Motores y USB Con el robot sobre la mesa y el programa corriendo, las ruedas pueden girar de golpe. Para probar, poner el robot con las ruedas en el aire (apoyado sobre un soporte o una caja).

1.2 Las pestañas

Fútbol y Mini Sumo están divididos en varios archivos .ino, que en el IDE aparecen como pestañas. Es solo para ordenar: al compilar, el IDE junta todas las pestañas en un único programa. Primero pone el archivo principal (el que tiene el mismo nombre que la carpeta) y después las demás en orden alfabético.

Dos reglas que salen de esto:

  • Una función se puede usar desde cualquier pestaña, sin importar en cuál esté escrita.
  • Los #define, constantes y variables globales van en el archivo principal. Así existen antes de que las otras pestañas los usen.

3. Cómo está armado un programa

Los tres archivos principales siguen el mismo orden. Una vez que se reconoce en uno, se reconoce en los otros.

Regla práctica para modificar: la mayoría de los cambios se hacen en la parte 2, cambiando un número. Cambiar la lógica del loop() ya es un cambio grande.

4. TestPlaca (repaso rápido)

Se sube antes de cargar Fútbol o Mini Sumo. Si algo falla acá, el problema es de armado o soldadura, no de programación. Es un único archivo, sin pestañas.

4.1 Uso

  1. Desconectar el HC-05 y subir TestPlaca.ino.
  2. Abrir el Monitor Serie a 9600 baudios. El programa va contando qué prueba en cada momento.
  3. Seguir las instrucciones: cuando lo pida, presionar cada pulsador (hay 10 s de margen).
  4. Para repetir todo, presionar RESET en el Arduino.

4.2 Secuencia de pruebas

4.3 Prueba de Bluetooth

Al terminar las pruebas automáticas, el loop() queda esperando caracteres y los devuelve (eco):

void loop() {
  if (Serial.available() > 0) {   // ¿llegó algo?
    char c = Serial.read();       // leerlo
    digitalWrite(PIN_LED_1, HIGH);
    tone(PIN_BUZZER, 2000, 80);
    Serial.write(c);              // devolverlo por el mismo canal
    delay(100);
    digitalWrite(PIN_LED_1, LOW);
  }
}
  • Sin HC-05: escribir en el Monitor Serie. Si vuelve la misma letra, el Arduino funciona.
  • Con HC-05: reconectar el módulo en J4, emparejar el celular (clave de fábrica habitual: 1234 o 0000) y enviar letras desde una app de terminal Bluetooth.
✔ Placa aprobadaSi las 5 pruebas dan bien, pasar a la sección 5.

5. Funciones comunes a Fútbol y Mini Sumo

Los dos programas comparten varias ideas. Se explican una sola vez acá.

5.1 Motores: Motores.ino

Estas tres funciones son idénticas en Fútbol y en Mini Sumo:

motorDerecho(velocidad)Mueve el motor derecho.

aplicarVelocidadMotor(pinA, pinB, velocidad)Hace el trabajo real con el DRV8833. Las dos anteriores la usan.

La velocidad es un número de −255 a 255:

Para girar se mueven las ruedas en sentido contrario: motorIzquierdo(-150); motorDerecho(150); gira en el lugar hacia la izquierda.

Si el robot va para el lado equivocado
  • Una rueda gira al revés → invertir los dos cables de ese motor en J7 o J8.
  • Dobla a la derecha cuando debería doblar a la izquierda → intercambiar los números de PIN_MOTOR_IZQ_* y PIN_MOTOR_DER_* en el archivo principal.
⚠ Mantener las dos copias igualesSi corrigen algo en Motores.ino de un programa, hagan el mismo cambio en el otro.

5.2 Pulsadores con INPUT_PULLUP

Los pulsadores se configuran con pinMode(pin, INPUT_PULLUP). Eso activa una resistencia interna que deja el pin en HIGH. Por eso la lógica queda al revés de lo que uno espera:

PulsadordigitalRead() devuelve
SueltoHIGH
PresionadoLOW

5.3 Detectar el flanco (“un toque = una acción”)

El loop() se repite miles de veces por segundo. Si solo se preguntara “¿está presionado?”, un toque de medio segundo cambiaría el modo cientos de veces. La solución es recordar cómo estaba el botón en la vuelta anterior y actuar solo en el instante en que pasa de suelto a presionado:

bool estadoActual = digitalRead(PIN_BOTON_TURBO);
if (estadoActual == LOW && estadoAnteriorBotonTurbo == HIGH) {
  // recién se presionó: actuar UNA vez
}
estadoAnteriorBotonTurbo = estadoActual;   // recordar para la próxima vuelta

Se usa en revisarBotonTurbo() (Fútbol) y en manejarEspera() (Mini Sumo). El delay(50) que sigue es un antirrebote: los contactos del pulsador “rebotan” unos milisegundos al cerrarse.

5.4 Buzzer y LEDs

  • tone(PIN_BUZZER, frecuencia, duración): por ejemplo, tone(PIN_BUZZER, 2000, 200) suena a 2000 Hz durante 200 ms sin frenar el programa.
  • digitalWrite(PIN_LED_x, HIGH / LOW) enciende o apaga un LED. En los dos programas los LEDs muestran qué está pensando el robot. Sirven mucho para encontrar fallas.

6.2 Archivo principal: Futbol.ino

a) Los #define

#define PIN_MOTOR_IZQ_A 9   // Motor 1A
#define PIN_MOTOR_IZQ_B 10  // Motor 1B
#define PIN_MOTOR_DER_A 3   // Motor 2A
#define PIN_MOTOR_DER_B 11  // Motor 2B

#define PIN_BOTON_BOCINA 2   // SW2 - bocina local
#define PIN_BOTON_TURBO  12  // SW3 - alterna modo turbo

#define PIN_LED_ENCENDIDO 4   // fijo mientras el programa corre
#define PIN_LED_ACTIVIDAD 7   // parpadea al recibir un comando
#define PIN_LED_TURBO     13  // fijo mientras el turbo esta activo

#define PIN_BUZZER 8

Nombran cada pin según su uso. Coinciden con la tabla de la sección 2.

b) Variables de estado

bool modoTurbo = false;
bool estadoAnteriorBotonTurbo = HIGH;

modoTurbo es la memoria del robot: indica si está en turbo o no. Se declara en el archivo principal porque la usan dos pestañas: Extras.ino la cambia y Motores.ino la lee para elegir la velocidad.

c) setup()

void setup() {
  pinMode(PIN_MOTOR_IZQ_A, OUTPUT);   // ... los 4 pines de motor como salida
  pinMode(PIN_BOTON_BOCINA, INPUT_PULLUP);
  pinMode(PIN_BOTON_TURBO, INPUT_PULLUP);
  pinMode(PIN_LED_ENCENDIDO, OUTPUT); // ... los 3 LEDs como salida
  pinMode(PIN_BUZZER, OUTPUT);

  Serial.begin(9600);            // velocidad de fabrica del HC-05

  detenerMotores();              // arrancar quieto
  digitalWrite(PIN_LED_ENCENDIDO, HIGH);
  tone(PIN_BUZZER, 1500, 150);   // bip corto de "listo"
}

Configura cada pin, abre la comunicación con el HC-05 a 9600 baudios y deja el robot quieto, con el LED 1 encendido y un bip de “listo”.

d) loop()

void loop() {
  revisarBotonBocina();
  revisarBotonTurbo();
  revisarBluetooth();
}

Son solo tres llamadas, que se repiten sin parar. En cada vuelta el robot revisa los dos pulsadores y si llegó un comando. Todo el trabajo está en las funciones de las otras pestañas.

⚠ El robot no frena solo Después de recibir F, el robot sigue avanzando hasta que llegue otra letra. La app del celular tiene que enviar S al soltar el botón. Hay que revisar eso en la configuración de la app.

Así se ve la parte central de revisarBluetooth():

char comando = Serial.read();

switch (comando) {
  case 'F':
    avanzar();
    break;
  case 'B':
    retroceder();
    break;
  // ... L, R, S, H
  default:
    // Caracter desconocido: se ignora.
    break;
}

El switch compara la letra con cada case. Cuando coincide, ejecuta hasta el break. Si no coincide con ninguna, va a default y no hace nada.

6.5 Modificaciones

Modificación 1 — Cambiar las velocidades (Motores.ino)

const int VELOCIDAD_NORMAL = 150;  // PWM (0-255) en modo normal
const int VELOCIDAD_TURBO  = 255;  // PWM (0-255) en modo turbo

Si el robot es difícil de controlar, bajar VELOCIDAD_NORMAL (por ejemplo, a 110). Por debajo de cierto valor los motores no llegan a arrancar: ese mínimo hay que encontrarlo probando.

Modificación 2 — Agregar un comando nuevo (Bluetooth.ino)

Objetivo: que la letra T active o desactive el turbo desde el celular, igual que el pulsador SW3.

  1. Elegir una letra que no esté en uso. F, B, L, R, S y H ya están ocupadas. Usamos T.
  2. Agregar el case dentro del switch de revisarBluetooth(), antes de default: 
        case 'H':
      tocarBocina();
      break;
    case 'T':
      modoTurbo = !modoTurbo;                           // invertir: true↔false
      digitalWrite(PIN_LED_TURBO, modoTurbo ? HIGH : LOW);
      break;
    default:
      break;
  3. Actualizar el comentario de la lista de comandos al principio de Futbol.ino, para que el próximo que lea el código sepa que existe la T.
  4. Verificar (✔). Si compila, desconectar el HC-05, subir el programa y reconectarlo.
  5. Probar: enviar T desde la app. El LED de D13 tiene que encenderse y, con F, el robot tiene que ir más rápido.
  6. En la app, asignar la letra T a un botón libre.
Por qué funciona sin tocar nada más modoTurbo está declarada en el archivo principal, así que se puede usar desde Bluetooth.ino. avanzar() ya pide velocidadActual(), que lee modoTurbo. El comando nuevo solo cambia esa variable y el resto del programa responde a ese cambio.

Para practicar: agregar un comando X que haga un “festejo”: tocar la bocina y girar a la derecha. Pista: se pueden llamar dos funciones dentro del mismo case.

7. Programa Mini Sumo

Robot autónomo: nadie lo controla durante la lucha. Tiene que decidir solo qué hacer. Para eso se organiza como una máquina de estados: en cada momento el robot está en un único estado, y cada estado tiene su comportamiento y sus condiciones para pasar a otro.

🛑 CHEQUEAR_BORDE En el código viene en false, para poder probar el robot sin sensores de borde conectados. Si quedan sin conectar, las entradas analógicas “flotan” y el robot entraría en EVASIÓN sin motivo. Antes de competir tiene que estar en true. Con false, el robot no ve el borde y se sale del ring.

c) La lista de estados

enum Estado {
  ESPERA,
  CUENTA_REGRESIVA,
  BUSQUEDA,
  ATAQUE,
  EVASION
};

Estado estadoActual = ESPERA;

Un enum es una lista de nombres posibles. estadoActual guarda en qué estado está el robot ahora. Siempre arranca en ESPERA.

d) setup()

void setup() {
  // pinMode de motores, pulsadores (INPUT_PULLUP), LEDs, buzzer,
  // TRIGGER (OUTPUT) y ECHO (INPUT)
  // Los sensores de borde se leen con analogRead(): no llevan pinMode.

  if (MODO_DEBUG_SENSORES || DEBUG_MOTORES) {
    Serial.begin(9600);   // el Monitor Serie solo se abre si se depura
  }

  detenerMotores();
  entrarEnEspera();
}

e) loop(): acá se toman las decisiones

void loop() {
  if (MODO_DEBUG_SENSORES) {
    imprimirLecturasDeBorde();
  }

  // 1) Parada de emergencia: prioridad absoluta
  if (botonEmergenciaPresionado()) {
    entrarEnEspera();
    return;                 // termina esta vuelta del loop acá
  }

  // 2) Según el estado actual...
  switch (estadoActual) {
    case ESPERA:
      manejarEspera();
      break;
    case CUENTA_REGRESIVA:
      manejarCuentaRegresiva();
      break;
    case BUSQUEDA:
    case ATAQUE:
      // 3) Primero el borde; recién después buscar o atacar
      if (CHEQUEAR_BORDE && hayBordeDetectado()) {
        manejarEvasion();
      } else if (estadoActual == BUSQUEDA) {
        manejarBusqueda();
      } else {
        manejarAtaque();
      }
      break;
    default:
      break;
  }
}

El orden de las preguntas marca la prioridad del robot:

7.3 Qué hace cada función de las otras pestañas

PestañaFunciónQué hace
MaquinaDeEstado.inoentrarEnEspera() / manejarEspera()Detiene los motores y apaga los LEDs. Espera un toque de SW2 (flanco, ver 5.3) para pasar a CUENTA_REGRESIVA.

7.4 Cómo mide el HC-SR04

digitalWrite(PIN_ULTRA_TRIGGER, HIGH);
delayMicroseconds(10);                 // pulso de 10 µs: "¡disparar!"
digitalWrite(PIN_ULTRA_TRIGGER, LOW);

unsigned long duracionPulso = pulseIn(PIN_ULTRA_ECHO, HIGH, 20000);
return duracionPulso / 58;             // µs → cm

El sensor emite un sonido y mide cuánto tarda el eco en volver. El sonido recorre unos 343 m/s: ida y vuelta de 1 cm tardan aproximadamente 58 µs. Por eso se divide por 58. El 20000 es un tiempo máximo de espera de 20 ms: si no vuelve eco, pulseIn devuelve 0 y el programa no queda trabado.

7.5 Calibrar los sensores de borde

  1. En MiniSumo.ino, poner MODO_DEBUG_SENSORES = true y subir el programa.
  2. Abrir el Monitor Serie a 9600 baudios. Sin presionar SW2, el robot queda quieto en ESPERA.
  3. Identificar cada sensor: tapar o acercar a una superficie blanca uno solo por vez y ver qué valor cambia. Corregir los #define SENSOR_BORDE_* si no coinciden.
  4. Apoyar el robot sobre el negro del ring y anotar los valores. Después sobre la línea blanca y anotar de nuevo:
    SensorSobre negroSobre blanco
    Izquierdo (A1)  
    Derecho (A2)  
    Frontal (A3)  
  5. Elegir UMBRAL_BORDE a mitad de camino entre el mayor valor sobre negro y el menor valor sobre blanco. Por ejemplo, con negro ≈ 150 y blanco ≈ 850, el umbral queda en 500.
  6. Volver MODO_DEBUG_SENSORES a false y poner CHEQUEAR_BORDE en true.
Ojo con el sentido de la comparación El programa usa lectura > UMBRAL_BORDE: da por hecho que el blanco da un número más alto que el negro. Si en sus sensores pasa al revés, hay que cambiar > por < en hayBordeDetectado() y en manejarEvasion().

7.6 Modificaciones

Modificación 1 — Distancia de detección (MiniSumo.ino)

El ring de Mini Sumo es chico. Con 40 cm, el robot puede “ver” a un alumno fuera del ring. Probar con valores más bajos:

const int DISTANCIA_DETECCION_CM = 30;

Modificación 2 — Cambiar el sentido de búsqueda (MaquinaDeEstado.ino)

Si el rival suele arrancar a la izquierda, conviene buscar para ese lado. Alcanza con invertir los signos:

void girarBuscando() {
  motorIzquierdo(-VELOCIDAD_BUSQUEDA);   // antes: +
  motorDerecho(VELOCIDAD_BUSQUEDA);      // antes: -
}

Modificación 3 — Velocidad de búsqueda (MiniSumo.ino)

Con VELOCIDAD_BUSQUEDA = 100 algunos motores no llegan a arrancar, o giran muy lento. Probar en el ring entre 90 y 160. Si gira tan rápido que pasa de largo al rival, bajar el valor.

Modificación 4 — Un sonido al detectar al rival (MaquinaDeEstado.ino)

  if (hayRivalDetectado()) {
    estadoActual = ATAQUE;
    digitalWrite(PIN_LED_BUSQUEDA, HIGH);
    tone(PIN_BUZZER, 3000, 50);   // bip corto: "¡te vi!"
  }

Sirve para escuchar cuándo el robot cambia de estado mientras lucha.

⚠ La cuenta regresiva es reglamentaria No bajar CANTIDAD_BIPS_CUENTA_REGRESIVA ni la duración de cada bip para “ganar tiempo”: el reglamento exige una espera de 5 segundos antes de moverse. Verificar el valor exacto en el reglamento vigente de la LNR.

7.7 Lista antes de competir

  • CHEQUEAR_BORDE en true
  • MODO_DEBUG_SENSORES y DEBUG_MOTORES en false
  • UMBRAL_BORDE calibrado en el ring de la competencia (la iluminación cambia las lecturas)
  • Sensores de borde verificados: izquierdo, derecho y frontal en el pin correcto
  • SW3 (emergencia) detiene el robot
  • El robot gira hacia el lado correcto al buscar y avanza recto al atacar
  • Batería cargada
